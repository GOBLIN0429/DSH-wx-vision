# WeChat ⇄ DSH bridge

让一台 Mac 上的微信，接上一个真正有记忆、有工具、能看图的智能体。

没有 hook、没有注入、没有改客户端 —— 全部走**像素**：截图 → OCR → 判断 → 点鼠标。
代价是慢一点，换来的是**不碰微信本体、不挑版本、没有封号风险**（微信看不到这一层）。

```
微信来消息
   ↓  像素检测（会话区 / 群列表 两块哈希）
   ↓  截图 + macOS Vision OCR
   ↓  分栏 / 气泡 / 发言人识别
   ↓  POST /api/session/prompt  注入 DSH 会话
   ↓  智能体读上下文、看图、查资料、决定怎么回
   ↓  wxsend：点输入框 → 剪贴板粘贴 → 回车 → 双重校验
微信群里出现回复
```

---

## 为什么这样做

微信个人号没有官方 API。要在群里像个人一样说话，只有两条路：

| 路线 | 能进群 | 封号风险 | 版本 |
|---|---|---|---|
| hook / 注入客户端 | ✅ | ⚠️ 高（改了签名，完整性校验能看见） | 钉死某个微信版本 |
| 官方 iLink 机器人 | ❌ 只能 1 对 1 | ✅ 零 | — |
| **像素自动化（本项目）** | ✅ | ✅ 低（客户端零改动） | 任意版本 |

一个实测结论：`deepseek-flash` **不支持图片输入**（传图返回 200 但内容为空，图片被静默丢弃）。
所以识图走的是「存成文件 + 让智能体用 `read_image` 工具看」，不是内联图片块。

## 结构

```
src/        Swift 命令行工具（检测、点击、几何、OCR）
py/         Python 逻辑（桥、多群仲裁、发送、控制）
bin/        编译产物（gitignore，用 ./build.sh 生成）
persona/    人格文件，需拷贝到会话工作区作为 AGENTS.md
wxstart.sh  启动（先清理残留 → 固定窗口几何 → 起桥）
wxstop.sh   停止（取消会话 → 杀进程 → 校验干净）
```

### Swift 工具

| 工具 | 作用 |
|---|---|
| `wxwatch` | 常驻检测器：ScreenCaptureKit 2fps 流，对**会话区**和**群列表**分别做稀疏哈希，变化时输出 JSON 事件 |
| `wxtool` | 鼠标点击 / Cmd+V / 回车 |
| `wxgeom` | 把微信窗口固定到标准几何，漂移会自动拉回 |
| `ocrjson` | Vision OCR，输出带坐标和置信度的 JSON |
| `winlist` / `wpid` | 按窗口标题 / 进程名查找 |
| `activate` | 把微信提到前台 |

### Python

| 脚本 | 作用 |
|---|---|
| `wxbridge.py` | 单群桥：检测 → 读取 → 注入。含分栏/气泡/发言人识别 |
| `wxmulti.py` | 多群：两条信号仲裁（当前群优先，另一个群有新消息才切） |
| `wxsend.py` | 发送，草稿与结果双重校验 |
| `wxread.py` | 会话行的聚类与分栏 |
| `wxctl.py` | 会话状态查询 / 取消 |
| `wxbalance.py` | 查 DeepSeek 余额（直连接口，不点界面上的鲸鱼） |
| `media.py` | 媒体区域检测（实验性） |

## 跑起来

### 前置

- macOS + 微信（任意较新版本）
- DSH Desktop（提供会话注入的 HTTP 接口）
- 系统设置里给 **DSH Desktop** 授予：
  - **屏幕录制**（截图）
  - **辅助功能**（控制鼠标键盘）

### 构建

```bash
./build.sh
```

### 准备会话

在 DSH 里建一个专门的工作区（例如 `wechat-chat/`），把 `persona/AGENTS.md` 拷进去。
人格就是那个文件 —— 它决定「对谁热情、对谁生疏、什么能办、什么要请示」。

### 启动

```bash
./wxstart.sh
```

它会：清理上次残留 → 把微信窗口固定到 `(820,60) 800×889` → 连会话 → 起检测器。
设置会话 ID 用环境变量 `WX_SESSION`。

### 停止

```bash
./wxstop.sh
```

**只杀进程是停不干净的。** 注入到会话里的任务会让那个智能体继续自己跑、继续操作微信。
所以停止分四层，任何一层没清干净就以非零码退出：

1. `session/cancel` 并轮询等到队列真的空了
2. 终止进程（先 TERM，超时再 KILL）
3. `pgrep` 校验五个进程名
4. 校验目标会话确实停了

## 几个非显然的实现细节

这些是踩过坑之后定下来的，改代码前值得看一眼。

**窗口几何必须钉死。** 所有坐标（点击点、OCR 裁剪区、哈希区域）都是从窗口矩形推出来的，
窗口一挪全部错位。`wxgeom` 负责固定并自愈。

**昵称和气泡不能靠位置区分。** 微信 Mac 里昵称和气泡**左对齐**，x 只差约 29px。
真正可靠的判据是**文字背后的底色**：面板底色 30、别人气泡 47、自己气泡 134。

**图片里可能有文字。** 一张截图会有大量 OCR 结果混进「聊天记录」。
检测到图片区域后，落在框内的行必须剔除。

**图片检测不能靠颜色或方差。** 气泡和照片在两者上都分不开。
可用的是「文字空洞」——图片气泡里没有字，会在文字行之间留下远大于正常间距的空白
（正常消息间距 54–127px），再向外扩张 50% 补全被裁掉的边缘。

**输入框里的文字不是消息。** 排版区（窗口高度 80% 以下）要整体排除，
否则你正在打的字会被当成群里的新消息。

**发送前必须重新确认微信在前台。** `Cmd+V` 送给的是最前面的应用。
DSH 自己在跑的时候就是最前面的那个，不检查的话粘贴全进了 DSH。

**中文必须走剪贴板。** `CGEvent` 直接打键会撞输入法状态，打不出中文。

**校验要看清对象。** 早期版本用整窗 OCR 找回复文本，群里别人说过同样的字就误判成功。
现在草稿只校验输入框区域，发送只校验输入框是否清空。

**检测器只能有一个。** 两个 `wxwatch` 同时跑会抢同一个窗口的 ScreenCaptureKit 流，
输的那个静默停止 —— 表现为「桥突然什么都收不到了」。

## 已知限制

- **慢**：一次完整往返 5–15 秒，主要花在 OCR（~0.8s）和智能体推理上
- **分栏线检测不稳**：窗口里出现强边缘（图片边框、图标栏）时可能算错，已加区间钳制兜底
- **切群靠点击**：列表随消息重排，点错会切到别的群；切完会校验标题
- **像素依赖**：改字号、改窗口大小、微信大改版都可能需要重新校准
- **只处理文本和图片**：语音、表情、文件还没有解析

---

## 安全

- 不改微信客户端，不注入，不 hook
- 凭据不落在仓库里（`DEEPSEEK_API_KEY` 由 DSH 自己在 `$DSH_HOME/.credentials.yaml` 管理）
- 本方案能看到屏幕上的内容，建议在专用账号/小号上使用
- 「主人」是按微信昵称识别的 —— **任何人改名成「主人」都会被当成主人**。
  生产使用建议加暗号或二次确认
